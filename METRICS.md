# Документация по метрикам

В этом документе описаны все метрики и поля данных, передаваемые и обрабатываемые сервером.

## Обзор

Система принимает телеметрические данные GPS и сотовой сети через ZMQ на порту `7777`. Данные ожидаются в формате JSON и записываются в журнал `./Location_save_data/received_data.jsonl`.

---

## 1. GPS/Локация

| Поле | Ключ в JSON | Тип | Единица | Описание |
|------|-------------|-----|---------|----------|
| Широта | `location._Latitude` | `double` | градусы | Географическая широта (-90 до 90) |
| Долгота | `location._Longitude` | `double` | градусы | Географическая долгота (-180 до 180) |
| Высота | `location._Altitude` | `double` | метры | Высота над уровнем моря |
| Метка времени | `time` | `long long` | миллисекунды | Unix-метка времени точки данных |

---

## 2. Метрики сотовой сети

Данные сотовой сети передаются в массиве по ключу `cells`. Каждая запись содержит метрики, специфичные для типа сети.

### 2.1 LTE (4G)

| Поле | Ключ в JSON | Тип | Единица | Описание |
|------|-------------|-----|---------|----------|
| Идентификатор ячейки | `ci` | `int` | - | Cell Identity — уникальный идентификатор ячейки LTE |
| Физический идентификатор | `pci` | `int` | - | Physical Cell Identity (0–503) |
| Код зоны отслеживания | `tac` | `int` | - | Tracking Area Code для отслеживания местоположения |
| RSRP | `rsrp` | `int` | dBm | Мощность опорного сигнала (-140 до -44 dBm). Чем выше значение, тем сильнее сигнал |
| RSRQ | `rsrq` | `int` | dB | Качество опорного сигнала (-20 до -3 dB). Чем выше значение, тем лучше качество |
| RSSI | `rssi` | `int` | dBm | Индикатор общей принятой мощности — суммарная мощность всех принятых сигналов |
| Опережение времени | `ta` | `int` | - | Timing Advance (0–1282), указывает на расстояние от базовой станции |

### 2.2 NR (5G)

| Поле | Ключ в JSON | Тип | Единица | Описание |
|------|-------------|-----|---------|----------|
| Идентификатор ячейки NR | `nci` | `long long` | - | NR Cell Identity — уникальный идентификатор ячейки 5G |
| Физический идентификатор | `pci` | `int` | - | Physical Cell Identity (0–1007) |
| Код зоны отслеживания | `tac` | `int` | - | Tracking Area Code для отслеживания местоположения |
| SS-RSRP | `ssRsrp` | `int` | dBm | Мощность сигнала синхронизации. Аналог RSRP для 5G |
| SS-RSRQ | `ssRsrq` | `int` | dB | Качество сигнала синхронизации. Аналог RSRQ для 5G |
| SS-SINR | `ssSinr` | `int` | dB | Отношение сигнал/(шум+помехи) для сигнала синхронизации. Чем выше значение, тем лучше качество сигнала |

### 2.3 GSM (2G)

| Поле | Ключ в JSON | Тип | Единица | Описание |
|------|-------------|-----|---------|----------|
| Идентификатор ячейки | `ci` | `int` | - | Cell Identity — уникальный идентификатор ячейки GSM |
| Код зоны обслуживания | `lac` | `int` | - | Location Area Code |
| RSSI | `rssi` | `int` | dBm | Индикатор уровня принятого сигнала |
| Опережение времени | `ta` | `int` | - | Timing Advance (0–63), указывает на расстояние от базовой станции |
| BSIC | `bsic` | `int` | - | Код идентификации базовой станции (0–63) |
| ARFCN | `arfcn` | `int` | - | Абсолютный номер радиоканала |
| Диапазон | `band` | `int` | - | Идентификатор частотного диапазона |

## 3. История сигнала

Система ведёт временной ряд для визуализации уровня сигнала:

| Тип сети | Отслеживаемая метрика | Формат идентификатора ячейки |
|----------|-----------------------|------------------------------|
| LTE | RSRP | `lte_{ci}` |
| NR (5G) | SS-RSRP | `nr_{nci}` |
| GSM | RSSI | `gsm_{ci}` |

- **Максимум точек истории**: 200 сэмплов на ячейку
- **Таймаут устаревших данных**: 300 секунд (записи старше 5 минут удаляются)

---

## 4. Фильтры

Система может возвращать флаги фильтров для управления передачей данных о местоположении:

| Фильтр | Ключ в ответе | Тип | По умолчанию | Описание |
|--------|---------------|-----|--------------|----------|
| Фильтр широты | `f_lat` | `bool` | `true` | Управляет передачей данных о широте |
| Фильтр долготы | `f_lon` | `bool` | `true` | Управляет передачей данных о долготе |
| Фильтр высоты | `f_alt` | `bool` | `true` | Управляет передачей данных о высоте |

## Протокол обмена данными

- **Транспорт**: ZMQ (ZeroMQ)
- **Тип сокета**: REP (Reply)
- **Порт**: 7777
- **Протокол**: TCP
- **Привязка**: `tcp://*:7777`

Сервер работает по схеме «запрос-ответ»: принимает JSON-данные, обрабатывает и записывает их в журнал, затем отправляет обратно конфигурацию фильтров.
